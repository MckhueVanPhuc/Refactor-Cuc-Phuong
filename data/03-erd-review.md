# Conceptual ERD Review

## 1. Relationship Catalog

The Mermaid labels are uppercase renderings of the 16 canonical S1 names; underscores only separate words visually and do not introduce aliases or additional entities. Cardinality is written from Entity A to Entity B. Sources: [Entity Dictionary](01-entity-dictionary.md) (S1 V2), [Spec M01](../docs/spec/spec-M01.md) v3.2, [Spec M02](../docs/spec/spec-M02.md) v3.3, [Spec M03](../docs/spec/spec-M03.md) v3.7, [CRUD Matrix](02-crud-matrix.md) (S2 V2).

## 2. Excluded Relationships

| Excluded concept/link | Reason not drawn |
|---|---|
| Revision → Checkpoint through `checkpointList` | Represented once as REL-022 between Route and Checkpoint. |
| JourneySnapshot → embedded Checkpoint/QRCode/content/image values | A snapshot contains immutable historical projections, not ownership of the mutable canonical source entities. Drawing these as direct entity associations would erase the source-versus-copy distinction. |
| JourneySnapshot → OfflinePackage manifest → SelectedRouteContext manifest → PlaySession frozen journey | The manifests/frozen journey are embedded value copies, not canonical entities. Confirmed owner relationships are represented without adding intermediate nodes. |
| OfflineRouteMap, RouteEssentials | Embedded values of OfflinePackage without identity of their own (S1 HC-005; M01 §6.1, §6.4). |
| OfflinePackage → SelectedRouteContext | Offline Start reads a package manifest, while online Start reads the current snapshot. No persistent direct association between the package and current handoff is declared. |
| Media → OfflineResource | OfflineResource stores image references/bytes copied from published media; the source does not declare an independent canonical Media-to-OfflineResource association lifecycle. |
| PendingSyncItem → SessionRecord through SessionSyncRecord | SessionSyncRecord is transport-only. The canonical business lineage is represented as PlaySession → SessionRecord without creating or joining through a transport entity. |
| SessionRecord → CheckpointVisit | SessionRecord contains immutable historical visit values copied through transport; they are not the same canonical M02 CheckpointVisit instances. |
| AuditRecord → affected Route/Checkpoint/QRCode/Revision/account entity | AuditRecord uses a generic `entityType`/`entityId` reference, and `revision` holds the `revisionNumber` of the Revision concerned (S1 HC-006). Separate cardinalities to each possible target are not declared, so polymorphic links are not drawn. |
| Actor fields (`createdByUserId`, `lastEditedByUserId`, `publishedByUserId`, `closedByUserId`, `fieldVerifiedByUserId`, `usageRightsConfirmedByUserId`) → AdminAccount | Recorded user IDs for history and display; only the AuditRecord actor (REL-007) is drawn, as in V1. |
| LanguagePreference → Revision/OfflineResource/PlaySession | LanguagePreference selects a render branch but explicitly does not own or mutate package/session/content state. It remains a standalone canonical entity. |
| Published Route, OfflineStationContent, LiveQrLookupResult/LiveStationContent, RouteJourneyMap, RPT-01 and RPT-02 | These are projections, views or report outputs rather than canonical entities. |
| Public QR link `{QR_PUBLIC_BASE_URL}/q/{qrIdentifier}` | Derived from `qrIdentifier`; not stored as a separate field (M03 §6.2). |
| RecommendationContext, report filters and UI state | These are transient contexts and do not have canonical persistence identity. |
| Provider identity/session/credential | Authentication-provider data is external; no ProviderIdentity canonical entity was approved. |
